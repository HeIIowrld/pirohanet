# 모도 해커톤 초기 기획안 (가제 오늘길)

이 문서는 해커톤의 초기 제품 범위와 비교 점수 가설을 기록합니다. 현재 구현과 공급자는 [README](../README.md)와 [경로와 교통 데이터](ROUTING.md)에서 확인할 수 있습니다.

**가제** 오늘길  
**주제** 컨디션과 약속 시간에 맞춰 이동 경로를 추천하는 AI 지도  
**한 줄 소개** 피곤한 날에는 걷거나 서 있는 부담이 적은 길을, 여유 있는 날에는 저장한 장소에 잠깐 들를 수 있는 길을 제안한다.

## 1. 기획 배경

퇴근 후 약속 장소까지 가는 길에서 가장 중요한 조건은 매일 다르다. 평소에는 빠른 길이 편하지만, 오래 서 있기 힘든 날에는 몇 분 더 걸리더라도 덜 붐비거나 환승이 적은 경로가 낫다. 반대로 시간이 남는 날에는 지도에 저장해 둔 서점이나 카페에 들르고 싶어도, 이동과 체류에 얼마나 걸릴지 다시 계산해야 한다.

첫 사용자는 **서울에서 대중교통으로 통근·통학하며, 이동 전후에 약속이 있는 사람**이다. 추천이 필요한 시점은 평소 경로를 그대로 이용하기 어려운 날이나 약속 전 여유가 생긴 날이다. 서비스는 출발 전에 그날의 조건을 반영한 선택지를 보여준다.

## 2. 서비스 흐름

1. **일정 확인** — Google Calendar에서 다음 대면 일정의 시간과 장소를 불러온다. 캘린더에 적힌 도착 시각이나 몇 분 전까지 도착하라는 안내를 우선 적용하고, 안내가 없으면 제목을 기준으로 도착 여유를 제안한다. 일반 약속은 5분, 회의·수업은 10분, 면접·공연·예약은 15분을 제안한다. 다음 일정 카드에서 여유를 바꾸면 경로 비교와 출발 알림에 같은 도착 목표를 적용한다. 출발 시각은 현재 시각을 기본으로 하고, 출발지·목적지·출발 시각·도착 목표를 직접 입력할 수 있다. 일정 시작 이후를 도착 목표로 입력하면 시작 시각을 적용한다.
2. **오늘 상태 선택** — ‘괜찮아요(1점)’부터 ‘녹초예요(5점)’까지 오늘 상태를 고른다. 필요하면 덜 걷기, 환승 줄이기, 혼잡 피하기 중 우선순위와 추가 이동 허용 시간을 정한다. 일정은 출발 가능 시각과 도착 마감 계산에 쓰고, 이동 컨디션은 사용자 입력을 우선한다.
3. **경로 비교** — 약속 시간에 맞출 수 있는 후보 중 ‘가장 빠른 길’, ‘편안한 길’, ‘저장한 곳 들르기’를 조건에 따라 표시한다. 총 소요 시간, 도보 시간, 환승 횟수, 혼잡 정보의 기준, 체류 시간과 예상 도착 시각을 비교할 수 있다. 저장 장소 한 곳과 체류 시간을 선택할 수 있다. 경유만 시간 조건을 넘으면 가능한 직행과 함께 도착 목표를 몇 분 넘는지 보여준다. 추가 이동 한도 때문에 경유가 제외되면 초과 시간을 표시한다. 직행도 도착 목표를 넘으면 조회된 직행 중 가장 이른 예상 도착과 지각 예상 시간을 안내한다.
4. **길안내** — 경로를 선택하거나 지도 길찾기를 열면 해당 경로에 맞춰 출발 알림을 조정한다. 알림에서 안내를 열면 그 시각과 조회한 이동 시간으로 도착을 다시 추정한다. 앱에서는 승차역·정류소, 노선과 방향, 환승·하차, 마지막 도보를 순서대로 보여준다. 실시간 도착 안내를 연동한 구간에서는 탑승 전에 도착 정보를 확인할 수 있다. 이동 중 상세 안내는 카카오맵이나 네이버 지도에서 이어서 볼 수 있다. 경유 경로는 ‘서점까지’와 ‘서점에서 약속 장소까지’로 연결한다.

## 3. 광화문 시연 시나리오

금요일 18시, 왕십리역에서 출발해 19시 세종문화회관 약속으로 이동한다. 도착 목표는 18:55이고, 교보문고 광화문점에 10분 머무를 수 있는지 확인한다.

## 4. AI 설계

| 구분 | 구현 방식 |
| --- | --- |
| **모델** | 자연어 입력에서 이동 선호를 추출한다. 예를 들어 “피곤한데 서점은 10분만 보고 싶어”에서 도보·혼잡 회피 선호와 희망 체류 시간을 읽는다. 추천 이유에 쓰는 수치는 경로 비교 로직에서 계산한다. |
| **컨텍스트** | 사용자가 입력한 컨디션과 선호, 확인한 출발지·목적지, 약속 시작 시각, 추가 이동 한도, 저장 장소, 교통 데이터의 종류와 기준 시각을 사용한다. |
| **도구** | 지도 API로 경로와 이동 시간을 조회한다. 경로 비교 로직이 도착 목표와 경유 비용을 계산한 뒤 도보·환승·혼잡 부담을 비교한다. LLM 연동이 끊겨도 버튼 입력과 규칙 기반 추천을 제공한다. |
| **자율성** | 앱이 후보 조회·비교·추천을 수행한다. 사용자가 일정 장소와 최종 경로를 확정하고 상세 안내를 시작한다. |

### 경로 특성 측정

| 특성 | 계산 기준 |
| --- | --- |
| 이동·도착 | 이동 시간은 도보·대기·탑승을 포함한 경로 조회값이다. 경유는 첫 구간 도착에 체류 시간을 더한 시점을 두 번째 구간의 출발로 잡는다. 예상 도착은 출발 시각에 두 구간의 이동 시간과 체류 시간을 더해 계산한다. |
| 도보 | 출발지에서 첫 탑승까지, 환승 중, 마지막 하차 후 목적지까지의 도보 시간을 합산한다. |
| 환승 | 첫 탑승 이후 다른 열차나 차량으로 갈아탈 때마다 1회로 센다. 같은 호선에서 방향을 바꿔 다시 타는 경우도 포함한다. |
| 예상 혼잡 | 지하철 구간별 호선·역·방향과 예상 탑승 시각에 맞는 30분 평균을 조회한다. 정보가 있는 구간의 혼잡도를 탑승 시간으로 가중해 표시하고, 전체 지하철 탑승 시간 중 정보가 있는 비율과 통계 기준을 함께 표시한다. |

혼잡 부담은 정보가 있는 구간마다 `탑승 시간(분) × max(0, 혼잡도 / 100 − 1)`을 계산해 합산한다. 예를 들어 혼잡도 130%인 구간을 10분 타면 부담은 3이다. 정보가 없는 구간은 ‘정보 없음’으로 표시한다. 첫 시연에서는 비교하는 직행 후보가 모두 지하철을 포함하고 지하철 탑승 시간 전체에 혼잡 정보가 있을 때 혼잡 항목을 적용한다. 그 외에는 모든 후보에 이동·도보·환승 항목을 동일하게 적용한다.

### 추천 순위와 카드 표시

먼저 도착 목표를 넘는 후보를 제외하고, 가장 빠른 직행 대비 추가 이동 한도를 적용한다. 경유의 체류 시간은 도착 목표를 검사할 때 포함한다. 다음으로 조건을 충족한 직행의 비교 점수를 계산한다. 점수가 낮을수록 우선하며, 동점이면 예상 도착이 빠른 경로를 우선한다.

`비교 점수 = 이동 시간 + 도보 시간 × 도보 가중치 + 환승 횟수 × 환승 가중치 + 혼잡 부담 × 혼잡 가중치`

가중치는 해당 부담을 줄이기 위해 몇 분을 더 쓸 만한지에 대한 초기 가설이다. 아래 혼잡 가중치는 초기값이며, 사용자가 ‘덜 걷기’, ‘환승 줄이기’, ‘혼잡 피하기’를 선택하면 해당 항목의 가중치에 2를 더한다. 혼잡 정보를 비교할 수 없으면 혼잡 우선순위가 순위에 반영되지 않았음을 표시한다.

| 컨디션 | 도보 가중치 | 환승 가중치 | 혼잡 가중치 |
| --- | ---: | ---: | ---: |
| 1점 · 괜찮아요 | 0.2 | 1 | 1 |
| 2점 · 조금 피곤해요 | 0.35 | 1.5 | 1.5 |
| 3점 · 피곤해요 | 0.5 | 2 | 2 |
| 4점 · 많이 피곤해요 | 0.8 | 4 | 3 |
| 5점 · 녹초예요 | 1 | 5 | 4 |

상황별 규칙은 직행 비교 점수에 부담을 더한다. 광화문·종로·시청 일대에서 출발하거나 도착하는 이동은 한국 시간 기준 주말 11~20시와 평일 07~10시·17~20시에 버스 탑승 시간의 20%를 비교 점수에 더한다. 기본 가산점은 최대 8점이며, 예상 도착부터 도착 목표까지 10분 이하로 남은 후보에는 1.5배를 적용한다. 이 가산점은 시간대 기준의 초기 가설로, 예상 도착 시각은 공급자 이동 시간으로 계산한다. 사용자가 회피 노선을 선택하면 그 노선 탑승 시간의 40%를 최대 8점까지 더한다. 두 규칙 모두 도착 목표와 추가 이동 한도를 충족한 후보의 순위에 영향을 준다.

가상의 비교 예시에서 우선순위 선택, 혼잡 항목, 상황별 가산점을 제외한 점수는 다음과 같다.

| 컨디션 | 빠른 길 · 35분 / 도보 11분 / 환승 1회 | 편안한 길 후보 · 41분 / 도보 6분 / 환승 0회 |
| --- | ---: | ---: |
| 괜찮아요 | **38.2** | 42.2 |
| 피곤해요 | **42.5** | 44.0 |
| 많이 피곤해요 | 47.8 | **45.8** |

‘많이 피곤해요’에서는 도보 5분과 환승 1회를 줄이는 가치를 `5 × 0.8 + 4 = 8분`으로 평가한다. 추가 이동 6분보다 크므로 41분 경로를 추천한다.

- **가장 빠른 길**은 도착 목표를 충족하는 직행 중 예상 도착이 가장 빠른 경로다. 추가 이동 한도의 비교 기준으로 사용한다.
- **편안한 길**은 도착 목표와 추가 이동 한도를 충족하는 직행 중 컨디션과 선호를 반영해 고른다. 가장 빠른 길과 같은 경로는 카드 하나로 표시한다. 다른 경로를 별도로 추천하려면 사용자가 지정한 우선순위에서 개선이 있어야 한다. 우선순위가 없으면 도보·환승·예상 혼잡 중 개선된 항목을 표시한다. 혼잡 개선은 비교할 수 있는 데이터가 있을 때만 제시한다.
- **저장한 곳 들르기**는 두 구간의 이동 시간과 체류 시간을 합한 예상 도착이 목표 이내이고, 체류를 제외한 추가 이동이 허용 범위 이내일 때 표시한다. 카드에 체류 시간, 예상 도착, 직행 대비 추가 이동 시간, 구간별 길안내를 제공한다.

추천 이유는 비교 로직에서 계산한 차이로 작성한다. 예를 들어 “6분 더 걸리지만 도보 5분과 환승 1회를 줄여요”라고 표시한다. 비교 점수는 순위 계산에 사용하고, 화면에는 실제 이동 시간과 부담의 차이를 표시한다. 추천 이유는 자연어 입력 연동 없이도 제공한다.

| **시연 연동** | 일정 불러오기 | Google Calendar 읽기 OAuth. 미리 잡힌 일정의 도착 시각은 조회 당시 경로 기준 추정치로 표시한다. [Google Calendar 설정](https://developers.google.com/workspace/calendar/api/quickstart/js) |
| **후속 연동** | 지도 경로선, 독립 도보 경로, 탑승 전 도착 안내, 자연어 선호 입력 | 카카오맵 REST API 및 JavaScript SDK, 서울시 실시간 지하철 도착 API, LLM 구조화 출력. [서울 실시간 도착](https://data.seoul.go.kr/dataList/OA-12764/F/1/datasetView.do) |
| **추가 검증** | 다음 서울 버스의 혼잡도, 지원 광역버스의 잔여 좌석 | 서울·경기 버스 도착 API. 잔여 좌석 수가 제공되는 차량만 **조회 기준 잔여 좌석**을 표시한다. 지하철에서는 평균 혼잡을 이용해 경로를 비교한다. [서울 버스](https://www.data.go.kr/data/15000314/openapi.do) · [경기버스 좌석 항목](https://gbis.go.kr/gbis2014/publicService.action?cmd=mBusArrivalStation) |

첫 시연에서 반드시 완성할 범위는 출발지·목적지·도착 목표의 수동 입력, 대중교통 직행과 저장 장소 경유 비교, 컨디션에 따른 추천과 근거, 도착 목표를 넘길 때의 안내다. 경로 카드에는 이동 단계와 카카오맵 길찾기 링크를 제공한다. 지도 경로선, 독립 도보 경로, 실시간 지하철 도착, 자연어 입력은 핵심 시연 흐름을 검증한 뒤 연결한다. 자연어 입력을 발표에 포함한다면 선호와 체류 시간을 입력값으로 채우는 한 장면으로 범위를 잡는다.

첫 시연을 완성한 뒤 실시간 칸별 혼잡도, 사용자 선택을 반영하는 취향 학습, 이동 기록과 공유를 단계적으로 검토한다. GPS 아트는 이동을 기록하고 공유하는 확장 아이디어로 다룬다.

## 6. 차별점과 검증 계획

지도 앱에서 주변 저장 장소를 찾을 수 있다. 오늘길은 **지금 들렀다 가도 약속에 맞출 수 있는지**, **몇 분을 더 쓰면 걷기·환승·혼잡 부담을 얼마나 줄일 수 있는지**를 같은 화면에서 보여준다. [네이버지도 주변 저장 장소 안내](https://help.naver.com/service/5637/contents/21480?lang=ko&osType=COMMONOS)

- **검증 방법** — 소규모 사용자 비교 테스트에서 일반 경로 화면과 개인화 비교 화면을 각각 보여준다. 피곤한 상황과 시간이 남는 상황을 모두 제시하고 화면 순서를 번갈아 배치한다. 실제 후보를 두고 환승 1회 또는 도보 5분을 줄이기 위해 몇 분 더 이동할 의사가 있는지 묻고, 답변과 경로 선택을 비교해 초기 가중치를 조정한다.
- **측정 항목** — 경로를 고르는 데 걸린 시간, 선택한 경로, 선택 이유, 예상 이동 부담과 만족도를 기록한다. 실제 이동도 해본 참가자에게는 도착 시각과 체감 혼잡을 추가로 묻는다. 실제 착석 결과는 해당 차량과 관측 시각을 맞춰 별도로 기록한다.
- **성공 기준** — 같은 출발지·목적지에서 피로도나 여유 시간에 따라 추천이 달라지고, 사용자가 비교 카드만 보고 선택 이유를 설명할 수 있어야 한다. 추천된 경유는 체류를 포함해 도착 목표를 충족해야 한다. 도착 목표를 앞당기면 조건을 벗어난 경유 카드가 사라지고 그 이유가 표시되어야 한다. 예상 혼잡은 통계 기준과 함께 표시하며, 실제 잔여 좌석을 연동하는 경우 조회 시각과 함께 표시한다.

## 7. 구현 순서

1. **수동 입력과 직행 비교** — 출발·도착 조건을 입력하고 대중교통 경로를 조회한다. 가장 빠른 길과 편안한 길의 차이, 도착 목표를 넘길 때의 안내를 표시한다.
2. **저장 장소 경유와 광화문 시연** — 직행과 경유 두 구간의 실제 응답을 확인한다. 경유 카드에 이동·체류 시간과 구간별 지도 링크를 붙이고, 두 시연 장면을 실제 후보로 검증한다.
3. **연동과 안내 확장** — 테스트 계정 일정으로 목적지와 도착 목표를 채운다. 지도 경로선, 독립 도보 경로, 실시간 도착 안내, 자연어 선호 해석은 시연에 필요한 순서로 연결한다.
